> 本文来自 Agora Arena 所基于的原版格斗引擎「神仙打架」（rockbenben，MIT），描述原版角色部件图的出图流程。Agora Arena 的十位原创角色使用逐帧精灵图集（`public/fighters/`、`scripts/build-fighter-atlases.mjs`），不依赖这套部件管线。

# 角色部件出图管线

美术是可选增强层：游戏本体永远用骨骼胶囊/锥形笔锋渲染，**逐件独立挂载**——
`public/chars/<id>/` 下存在哪个部件的 PNG 就用哪张贴图，缺的部件各自回退到
程序化绘制，不会崩、不会露洞、不需要任何开关。目录整个不存在时，效果等同
全部部件都缺，即完全回退成当前的纯程序化渲染。

## 0. 结论先行：只做头 + 躯干，不做四肢

Task 27 用占位图验证过，结论是**四肢不值得出图**，只生成 `head.png` +
`torso.png` 两张，每角色出图量从 6 张降到 2 张。理由是挂载尺寸：

| 部件 | 实际挂载尺寸 | 说明 |
| --- | --- | --- |
| 头 | 约 32×32 px | 独立一张 |
| 躯干 | 约 40×56 px | 独立一张 |
| 手臂/腿 | 约 22×26 / 26×32 px | **同一张图会被分别拉伸到大臂/小臂或大腿/小腿两段** |

四肢那张图不仅本身就小到画不出细节，还要同时兼容两段不同长度的骨骼拉伸，
画再精细也只会被压成一根均匀色管——花在四肢上的出图成本基本打水漂。角色
辨识度（这是哪吒还是悟空）全靠头（脸/发髻/抹额）和躯干（衣着/配色），这两
块才值得花生图配额。四肢继续用锥形笔锋渲染（Task 21：关节粗、末端细，墨色
描边 + 主色渐变），实测与贴图头/躯干放在一起不割裂（见下方验证结论）。

`parts.ts` 本身仍然支持逐件挂载任意子集——如果某个角色确实需要更强的四肢
辨识度（比如武器要贴在手上），照样可以补 `armF.png` 等文件，回退规则一视
同仁，不需要改代码——**前提是文件名在 `src/render/parts.ts` 的 `NAMES` 探测列表里**。
那张表现在只有 `head`/`torso`（理由见本文第 0 节：四肢不出图，探七件等于每个角色白付 5 个 404）。
要加四肢或兵器素材，除了放文件还得把名字加回那张表，否则它不会被加载、也不会报错。

## 1. 生成角色立绘

用 `ai-image-gen` skill 生成角色立绘：扁平厚描边卡通风、正侧身战斗站姿，纯色背景，
头部与躯干轮廓清晰分离（互不遮挡，方便下一步切件）。

Prompt 模板：

```
东方神话角色<名字>，扁平插画风格，粗黑描边，横版格斗游戏站姿侧身像，
纯白背景，半身可见（头肩至腰），鲜艳配色<主色>
```

**描边粗细要控制**：程序化四肢的描边固定 2px（`INK.ink`，逻辑像素）。贴图
的描边如果明显比这个粗（占位图验证时踩过这个坑，占位图描边给到 6~7px），
放在一起头/躯干会比四肢"重"一档，读出来是两种画风拼接，而不是同一角色。
出图或后期都要把描边粗细往程序化四肢的水平上收。

## 2. 切件

从立绘上切出两个部件，每件独立 PNG、透明背景：

| 文件名 | 部位 |
| --- | --- |
| `head.png` | 头 |
| `torso.png` | 躯干 |

（如确有需要，`armF.png`/`armB.png`/`legF.png`/`legB.png`/`weapon.png` 仍是
合法文件名，挂载规则与 head/torso 完全一致——见下方"挂载与回退规则"。）

切件要点：
- 切口留 10% 重叠余量，避免旋转到极限角度时关节处露出背景缝隙。
- 部件图整体按「宽度方向撑满、高度方向沿骨骼方向」设计：躯干挂载时会被
  缩放成宽 ≈ 40、高 ≈ 骨骼长度（`SHOULDER_Y - HIP_Y`）；头挂载时是固定
  32×32 的正方形，画的时候留够这个长宽比的余量。
- **躯干锚点方向：画面顶部 = 肩线，画面底部 = 腰线，不留边距**（`renderer.ts`
  的 `drawBoneImg(ctx, shX, shY, hipX, hipY, ...)` 起点=肩、终点=腰，与
  `parts?.torso` 挂载调用一致）。这个方向曾经反过来过——旧版调用是
  `drawBoneImg(ctx, hipX, hipY, shX, shY, ...)`（起点=腰），实测会把整张图
  在挂载时做一次 180° 点反转（画面顶部→腰、画面底部→肩，且左右也一并翻转），
  用一张四色象限测试图挂进 `#training` 截图验证过（Task 27 第二轮修的）。
  素材按「肩在上、腰在下、面朝右」自然画即可，不需要为了迁就挂载方向反着画。
- 躯干整个衣物形状要撑满画布（肩线贴顶、腰线贴底、宽度占满大部），不要画成
  "挂在画布中央、四周留白的服装展示图"——四周留白会在拉伸挂载时被压扁成
  真身体只剩一小条，甩出轮廓外的飘带/流苏/下摆反而被拉成视觉主体。
- 尺寸建议给到实际挂载尺寸的 3–4 倍（头 128×128、躯干 160×224），留缩放
  余量，做完之后确认缩小到实际游戏尺寸（角色约 150px 高）时五官仍然可辨——
  细节太碎会被缩没，眼睛/发型这类关键特征要画得够粗够大。

## 3. 朝向与镜像：只画一份，「面朝右」为准

游戏里角色会不断转身（每帧自动面向对手），但每个部件只有一个文件——没有
`head-left.png` 这种左右两份。转身时贴图靠代码镜像，不是靠美术出两套图。

**约定：所有部件图都按「角色面朝右」的姿势画**（Prompt 模板里的站姿侧身像默认就是
朝右）。面朝左时，引擎会把每一节骨骼各自的贴图内容在自己的锚点上做一次水平镜像
（不是简单旋转——旋转到骨骼方向只能保证贴图落在正确的位置和角度，画面内容本身
左右不对称的部分不会跟着换边，必须额外镜像一次）。这意味着：

- **非对称细节按"角色朝右站立"时应该出现的那一侧画**，比如哪吒的抹额飘带、
  二郎神的三只眼按朝右的姿势画。转身朝左时，花纹、朝向细节会跟着头/躯干一起
  翻到镜像位置，不用也不能手工再画一份"朝左版"——多画的朝左版反而会被再镜
  像一次，变成两次翻转，回到错的那一侧。
- 镜像是逐骨骼独立做的（躯干/头各自绕自己的锚点镜像，不是整个人物绕一个中
  心整体翻转），只要素材已经按「关节到关节」画好，镜像后关节位置依然精确
  对齐，不需要额外处理。Task 27 用占位图实测过这条镜像链路（非对称的抹额飘
  带 + 躯干腰带结都正确跟随 facing 翻面），结论成立。

## 4. 挂载与回退规则

放入 `public/chars/<charId>/`，文件名固定为 `head.png` `torso.png`（+ 可选的
`armF.png` `armB.png` `legF.png` `legB.png` `weapon.png`）。`charId` 对应
`src/data/characters/` 里角色的 `id` 字段（如 `wukong`、`erlang`、`niumo`、`nezha`）。

游戏在角色出场时会自动探测这一路径（`/chars/<charId>/<part>.png`）。**规则是
逐件独立的**：探测到哪个部件的图就用哪张贴图，缺的部件各自静默回退成当前的
程序化绘制（头→圆形胶囊，躯干→锥形笔锋，四肢→锥形笔锋），不影响可玩性，
不会半吊子拼接出"贴图缺了一半、旁边露出背景色"这种情况，控制台也不会报错
（图片加载失败走的是 `onerror`，不是异常）。目录整个不存在时，两个部件的探测
全部落空，效果等同完全回退到纯程序化渲染，和 Task 27 之前的行为一致。

## 5. 提示词的坑（每一条都是烧过配额换来的）

**约定写在文档里不等于写进了提示词。** 第 3 节的「面朝右」立了很久，而
`gen-parts.py` 里八处躯干一直写着 `Front view`——头三分侧面、身子正对镜头，
挂到侧身骨架上就是纸片人（雷震子那张最典型：两只翅膀左右平摊）。
接连两轮重出素材都把错的朝向烙得更深。现在有 `tests/artOrientation.test.ts` 挡着。

| 症状 | 成因 | 措辞 |
|---|---|---|
| 出正脸 | 只写 `Three-quarter view facing right` 太笼统；加否定句「不要正脸」也无效——**纯否定句只让模型退回最安全的选项** | 写成可执行几何：鼻梁压过远颊线、远颊被部分遮住、近耳全见远耳不见 |
| 整个头躺倒 90° | `rotated 35 degrees` 被理解成**旋转画面** | 写明转轴：头保持竖直、下巴水平、绕颈部**竖轴**水平转 |
| 并排画了两颗头 | 描述视角的措辞本身在暗示「多给几个视角」，包围盒把两颗都框进去，切出来是横条 | `one subject alone, not a character sheet, no side-by-side panels, no duplicates` |
| 整张脸被染成角色色 | `teal and white palette` 被应用到全图，出来是没有肤色的单色线稿 | 圈定范围：配色只管头发/冠饰/衣领，脸保持自然肤色；非人肤色（雷震子青绿、白骨精惨白）写明例外 |
| 躯干宽扁，挂上去横向压扁 | 模型默认把衣服画成一件摊开的平面 | 长宽比是**硬约束**不是构图偏好：挂载横向铺到 40、纵向铺到骨长 68，两轴独立，内容长宽比必须≈0.588 |
| 全员出图判成 TIMEOUT | 完成判据写死 `naturalWidth > 800`，那是照横图 1264×848 定的；提示词改成竖构图后模型出 617×1024，宽度不到 800 | **构图要求和完成判据是耦合的，改一个必须回头看另一个**。判据改用长边 |

**为解决问题 A 加的措辞，在 A 换了解法之后必须撤掉。** 「双颊可见」是早期为了让
铁扇公主的脸别太窄加的；等头改成按面积归一之后它就没用了，却一直留着，
并且在反向把模型往正脸拽——朝向卡了两轮都没找到原因。

**超时不等于没出图。** 判据认错时图往往已经生成，配额已经花掉。
`scripts/rescue.py` 把标签页上现成的图裁进 `_raw/`，零配额找回。
